Статус: рабочий черновик. Дата проверки: 17 октября 2026.

## Зачем нужен этот рабочий продукт

Помочь редактору найти первоисточник, понять границы его применимости и подготовить собственный документ с проверяемыми ссылками. После карты — возврат к [ранее запланированным редакторским продуктам](../vk-carousel/WORKPLAN.md): брифу, контент-плану и пакету сценариев.

Проверяемый результат: по конкретному рабочему вопросу можно выбрать репозиторий, найти нужный файл, указать источник и определить место собственного результата.

## Охват и хранение

Решение пользователя от 17 октября 2026: пока использовать сведения только из пяти публичных репозиториев организации MimEcoSys, перечисленных ниже. Ссылки из них на другие репозитории сами по себе не расширяют этот охват. Приватные репозитории не используются как источники этой карты.

Собственные рабочие материалы сохраняются в [dariakamishanova-sys/YoutobeMIM](https://github.com/dariakamishanova-sys/YoutobeMIM). Это точное найденное имя репозитория; пользователь назвала его «youtobeMIMI». Репозиторий публичный: размещаемые документы доступны всем.

## Связи, подтверждённые источниками

- PACK-ecosystem описывает целое; PACK-MIM — организацию МИМ внутри экосистемы; PACK-digital-platform — знания об ИТ-платформе. Основание: README этих репозиториев.
- PACK-MIM указывает docs как получателя материала для руководств. Это связь знания с его представлением; она не подтверждает актуальность каждого текста docs.
- PACK-MIM ссылается на mim-strategy как на источник форм предложения помощи. При использовании конкретной формулировки читаем соответствующий документ стратегии.
- В PACK-digital-platform есть [описание навигации знаний](https://github.com/MimEcoSys/PACK-digital-platform/blob/main/pack/digital-platform/02-domain-entities/DP.NAV.001-knowledge-navigation.md): реестр → манифест → карта Pack → кросс-ссылки. Документ имеет статус draft. Его маршрут применяем к доступным источникам; упомянутый им внешний реестр не входит в текущий охват.

## Как читать и готовить изменения

1. Сформулировать рабочий вопрос и выбрать репозиторий по таблице.
2. Прочитать README, затем манифест и границы области, если они есть.
3. Найти конкретный файл через индекс, карту или поиск внутри репозитория. Перед цитированием прочитать нужный раздел.
4. Зафиксировать ссылку, заголовок/раздел, дату проверки и статус источника. Для воспроизводимой версии можно использовать постоянную ссылку GitHub на конкретный коммит.
5. Подготовить собственный вывод или адаптацию в YoutobeMIM, отделив её от утверждения первоисточника.
6. Если обнаружена проблема в источнике, сначала описать её со ссылками. Правила внесения изменений в корпоративный репозиторий и полномочия редактора нужно выяснить отдельно.

README PACK-MIM и PACK-ecosystem содержат режим подписчика «только для чтения». Он не устанавливает права сотрудника, но и видимость репозитория не доказывает право записи. В текущей работе исходные корпоративные документы используются для чтения, собственные результаты сохраняются здесь.

## Проверка методологии при подготовке документа

Этот список — рабочая проверка для текущего редакторского проекта, а не утверждение о полном стандарте МИМ.

- [ ] Названы получатель, его рабочий вопрос и назначение документа.
- [ ] Указаны границы: что документ описывает и чего по нему нельзя заключить.
- [ ] Различены объект, его описание и файл, в котором хранится описание.
- [ ] Для содержательных утверждений указаны конкретные первоисточники.
- [ ] Факты источника, собственные выводы, гипотезы и открытые вопросы различимы.
- [ ] Метод описывает способ действия; рабочий продукт — проверяемый результат этого действия.
- [ ] Сохранены важные различения: экосистема и организация МИМ; знание Pack и текст руководства; предложение и осуществлённая работа.
- [ ] Для результата заданы критерии готовности и фактический статус; сохранение файла не приравнивается к его приёмке.

Основания: разграничения в README PACK-MIM, PACK-ecosystem и PACK-digital-platform; различение предложений и результатов в README mim-strategy; требования приёмки существующего редакторского плана. Для каждого будущего документа проверка уточняется по его предмету и конкретным источникам.

## Открытые вопросы и расхождения

1. В PACK-MIM README исключает «методику обучения как таковую», а манифест включает методику и перечисляет соответствующие методы. При работе над такой темой нужно проверить конкретные актуальные файлы и отметить расхождение, не выбирать трактовку молча.
2. README и манифесты могут содержать разные версии и количества сущностей. Полноту состава нельзя выводить только из обзорного текста.
3. Не проверены все вложенные руководства docs; для выбранных редакторских тем нужны отдельные ссылки и проверка содержания.
4. Корпоративный порядок согласования правок и принимающие лица пока не установлены.
5. Применимость карты к самостоятельной работе пользователя ещё не проверена.
